## 3. 数据模型层（M1: `model/`）

### 3.1 ParameterModel

`frozen=True, slots=True`。每个参数包含最多 7 个预定义属性：

| 属性 | 枚举名 | 说明 |
|---|---|---|

| `dimension` | DIMENSION | 维度 |

空 `tuple` 表示该属性不参与组合。`expand_variables()` 按 `PARAMETER_ATTRIBUTES` 遍历顺序展开为 `VariableModel[]`。

### 3.2 VariableRegistry & ValueRegistry

- `ValueRegistry`: 值去重注册，相同值返回已有 ID

### 3.3 GeneratorConfig

聚合 `parameters`、`constraints`、`variable_registry`、`value_registry`。

## 4. 约束引擎层（M2: `constraint/`）

### 4.1 编译管线

```
表达式字符串 "x.dtype in ['FLOAT16'] and x.range_value in ['Zero', 'One']"
  │ ConstraintCache.get(expr) → None (miss)
  v
ConstraintParser.parse(expr)
  │ ast.parse(mode="eval") → ast.Expression
  v
ASTAdapter.validate(tree)
  │ ast.walk(tree) 检查每个节点是否在 SUPPORTED_NODES 白名单中
  v
DependencyAnalyzer.analyze(tree)
  │ visit_Attribute → "x.dtype", "x.range_value"
  v
CompiledConstraint(expression, tree, dependencies)
```

### 4.2 ASTAdapter 白名单

**`SUPPORTED_NODES` 列表**：

| 分类 | 节点类型 |
|------|----------|
| 根节点 | `ast.Expression` |
| 变量 | `ast.Name`, `ast.Attribute`, `ast.Load` |
| 常量 | `ast.Constant` |
| 比较 | `ast.Compare`, `Eq, NotEq, Gt, GtE, Lt, LtE, In, NotIn` |
| 布尔 | `ast.BoolOp`, `And, Or` |
| 一元 | `ast.UnaryOp`, `Not`, **`ast.USub`**, **`ast.UAdd`** |
| 条件 | `ast.IfExp` |
| 字面量 | `ast.List`, `ast.Tuple`, `ast.Set`, `ast.Dict` |
| 算术 | `ast.BinOp`, `Add, Sub, Mult, Div, FloorDiv, Mod` |

`USub` 和 `UAdd` 用于支持负数常量（`-1`）和正号（`+1`）。

### 4.3 ConstraintEvaluator

基于 `ast.NodeVisitor`，零 `eval()`/`exec()`。关键 visit 方法：

| 方法 | 说明 |
|---|---|
| `visit_Constant` | 返回常量值 |
| `visit_Name` | 从 context 字典取值 |
| `visit_Attribute` | 链式访问（支持 dict key / getattr） |
| `visit_Compare` | `==`, `!=`, `>`, `>=`, `<`, `<=`, `in`, `not in` |
| `visit_BoolOp` | `and` 短路（发现 False 停止），`or` 短路（发现 True 停止） |
| `visit_UnaryOp` | `not`, `USub`(-), `UAdd`(+) |
| `visit_BinOp` | `+`, `-`, `*`, `/`, `//`, `%` |
| `visit_IfExp` | 三元表达式 |
| `visit_Call` | 通过 FunctionRegistry 的白名单函数 |
| `visit_List/Tuple/Set/Dict` | 集合字面量 |

### 4.4 CombinedConstraint（`engine.py`）

```python
class CombinedConstraint:
    compiled: list[CompiledConstraint]  # 暴露给 PairExistenceChecker

    def evaluate(self, context) -> bool:
        for cc in self.compiled:
            try:
                if not evaluator.evaluate(cc.tree, context):
                    return False
            except Exception:
                continue              # 单条约束异常不终止整体
        return True
```

- 每条约束独立 try/except，异常不中断整体
- `compiled` 列表暴露为属性，供 M3 `PairExistenceChecker._is_pair_deep_valid` 逐约束访问

## 5. 覆盖率模型层（M3: `coverage/`）

### 5.1 Factor & FactorValue

```python
Factor(parameter="x", attribute="dtype")   # "x.dtype"
FactorValue(factor=Factor(...), value="fp16")  # x.dtype = fp16
```

### 5.2 Pair

`frozen=True`，`__post_init__` 自动 `normalize()` 排序 `(left, right)`。

```python
Pair(left=FactorValue(x.dtype=fp16), right=FactorValue(x.dimension=2))
pair_id = hash(pair)  # 整数 ID，进程内确定性
```

### 5.3 PairBuilder

`itertools.combinations(factor_values, 2)`，跳过 `left.factor == right.factor`（同一属性的不同值不配对）。

### 5.4 PairUniverse

PairUniverse 有两套 ID：**PairId**（哈希，Pair 自带的"身份证号"）和 **顺序索引**（加入 Universe 后才分配的"床位号"，0..N-1）。

#### 设计 PairId 的目的

O(1) 查重。没有 PairId，判断"这个 Pair 是否已在 Universe 中"就只能遍历列表逐一比较——O(n)。PairId = `hash(pair)` 将 Pair 映射为整数，配合 `Dict[PairId, Pair]` 实现 `pair_id in _pairs` 的 O(1) 查询。同构 Pair 在进程内始终产生相同哈希值（不可变 dataclass 保证）。

#### 两套 ID 的分工

```
Pair 对象
    │  pair_id = hash(pair)      ←── 构造时就确定，不依赖 Universe
    │
    ├── universe.add(pair)
    │     pair_id 已存在 → 跳过  ←── 防御性保护，正常流程不会触发
    │     pair_id 不存在 → idx = size()  ←── 此时才分配顺序索引
    │
    └── get_index(pair) → idx    ←── 用 PairId 查 _indices 字典拿到顺序索引
```

`PairBuilder.build()` 使用 `itertools.combinations` 生成全量组合，每个 Pair 只出现一次，正常流程不存在重复添加。`add()` 中的判重是**防御性保护**，防止外部误调用破坏数据结构。

| ID | 生成时机 | 特点 | 用途 |
|----|---------|------|------|
| **PairId**（`hash(pair)`） | Pair 构造后立刻可算 | 任意上下文均可独立计算 | O(1) 查重、`_pairs` 字典 key、跨模块引用 |
| **顺序索引**（0..N-1） | `universe.add(pair)` 时分配 | 密集连续，才能做位向量下标 | 位向量 bit 位置 |

#### 内部结构

```python
_pairs: Dict[PairId, Pair]             # PairId → Pair（主存储，PairId 查重 → O(1)）
_indices: Dict[PairId, int]            # PairId → 顺序索引 / bit 位置
_pairs_by_index: Dict[int, Pair]       # 顺序索引 → Pair

get_index(pair) → int | None           # 查 _indices[pair.pair_id]，无则说明不在 universe 中
get_by_index(idx) → Pair | None        # 按 bit 位置恢复 Pair
```

#### 为什么不用顺序索引直接查 Pair

判断 "Pair 是否在 Universe 中" 只能用 PairId，因为**顺序索引要加入之后才有**。Pair 从外部传入时（如 testcase 构建的 Pair），还没有顺序索引，只能用 `hash(pair)` 算 PairId 去查 `_pairs`。

而位向量必须用顺序索引——每个 bit 对应一个 `0..N-1` 的下标，才能做到 `O(1)` 置位和位与运算。如果直接用 PairId（可能几百亿的哈希值）作 `1 << pair_id`，会生成极端巨大的 Python `int`，操作效率极低。顺序索引保证 `0..N-1` 的紧凑范围。

#### 使用场景

| 操作 | 用哪个 | 原因 |
|------|--------|------|
| 判断 Pair 是否已存在 | PairId | `pair_id in _pairs`，不需要顺序索引 |
| 标记已覆盖 | 顺序索引 | 位向量 `covered_mask \|= (1 << idx)` |
| 遍历未覆盖 Pair | 顺序索引 | `uncovered_indices()` → `get_by_index(idx)` |
| 计算 testcase 增益 | 顺序索引 | `(testcase_mask & uncovered_mask).bit_count()` |

### 5.5 CoverageTracker — 位向量覆盖判定

使用 Python `int` 作为位掩码。核心规则：**`_covered_mask` 的第 `i` 位 = 顺序索引 `i` 的 Pair 是否已覆盖**。

```python
_covered_mask: int     # 位向量
_covered_count: int    # 维护计数

mark_covered(pair):
    idx = universe.get_index(pair)   # Pair → 顺序索引
    bit = 1 << idx                    # 对应 bit 位置
    if not (covered_mask & bit):      # 尚未覆盖？
        covered_mask |= bit           # 置位
        covered_count += 1            # 维护计数

uncovered_pairs_mask():
    all_bits = (1 << total) - 1 # total为universe中pair的总数，这里是5
    return all_bits & ~covered_mask     # O(1) 位运算
```

#### 示例

假设 Universe 有 5 个 Pair：

| 顺序索引 | Pair |
|----------|------|
| 0 | `Pair(left=x.dtype=FLOAT16, right=weight1.dtype=INT8)` |
| 1 | `Pair(left=x.dtype=FLOAT16, right=weight1.dtype=BF16)` |
| 2 | `Pair(left=x.dtype=INT8, right=weight1.dtype=INT8)` |
| 3 | `Pair(left=x.dtype=INT8, right=weight1.dtype=BF16)` |
| 4 | `Pair(left=x.is_present=True, right=weight1.is_present=True)` |

**初始**：`_covered_mask = 0`，全未覆盖。示例假设 Universe 有 5 个 Pair，因此用 5 位二进制示意（实际 `_covered_mask` 是 Python 任意精度整数，占用 bit 数 = Universe 中 Pair 总数，如 aclnnFFNV3 约 56,141 bit ≈ 7KB）。

**加入一个 testcase**（包含 `x.dtype=FLOAT16, weight1.dtype=INT8, x.is_present=True, weight1.is_present=True`）：

```
PairBuilder.build(testcase.values)
  → [Pair(x.dtype=FLOAT16, weight1.dtype=INT8),     # 顺序索引 0
     Pair(x.is_present=True, weight1.is_present=True)]  # 顺序索引 4

CoverageTracker.update(pairs):
  mark_covered(Pair(0)):
    idx = 0, bit = 1 << 0 = 0b00001
    covered_mask & bit = 0           → 未覆盖
    covered_mask |= bit              → covered_mask = 0b00001, covered_count = 1

  mark_covered(Pair(4)):
    idx = 4, bit = 1 << 4 = 0b10000
    covered_mask & bit = 0           → 未覆盖
    covered_mask |= bit              → covered_mask = 0b10001, covered_count = 2
```

**标记后**：`_covered_mask = 0b10001`（bit 0 和 4 = 1，bit 1/2/3 = 0）。

**查询**：

```python
is_covered(Pair(1)):    idx=1, bit=0b00010   # 第 1 bit
                        covered_mask & bit = 0b10001 & 0b00010 = 0 → False

is_covered(Pair(0)):    idx=0, bit=0b00001   # 第 0 bit
                        covered_mask & bit = 0b10001 & 0b00001 = 1 → True

uncovered_pairs_mask():
  # total = 5 (Universe 中 Pair 总数)
  all_bits = (1 << 5) - 1 = 0b11111           # 低 5 位全 1
  # covered_mask = 0b10001                    # bit 0、4 已覆盖
  return 0b11111 & ~0b10001 = 0b01110          # 剩下的 bit 1/2/3 未覆盖
```

**`_compute_gain_fast` 使用 `uncovered_pairs_mask()`**：从 testcase 提取所有 FactorValue → `PairBuilder.build()` 生成该 testcase 包含的全部 2-way 组合 → 逐 pair 查 Universe 得顺序索引 → 设 bit 构成 `testcase_mask` → 与 `uncovered_pairs_mask()`（即 `all_bits & ~covered_mask`，只取低 `total` 位的未覆盖位）做位与 + `bit_count()`，一次得到覆盖了多少未覆盖 pair。全过程无需遍历、无需比较、O(1)。

### 5.6 PairExistenceChecker — 方向 B

**方向 B** 的核心是对原始 2 值 pair 进行深度可达性验证，不仅检查 pair 自身的取值，还通过枚举缺失参数的取值域来判断该 pair 是否能出现在至少一个合法的完整用例中。

```python
_is_pair_deep_valid(pair) -> bool:
    1. 构建 base_context（pair 的 2 个值）
    2. 遍历每条已编译约束 (cc):
       统计依赖中未在 base_context 中出现的参数 → missing_by_param

       Case 1: 缺失 = 0
           → 直接 evaluate(cc.tree, base_context)
           → False → return False（此 pair 不可达）
           → True → 继续下一条约束

       Case 2: 缺失 ≥ 2 个参数
           → 无法穷举，continue（放过此约束）

       Case 3: 缺失 = 1 个参数的部分属性
           → 枚举该参数所有缺失属性的取值域的笛卡尔积
           → 组合数上限 100（超过则放过）
           → 任意一组满足约束 → 继续下一条约束
           → 全部不满足 → return False（此 pair 不可达）

    3. return True（所有约束均通过或放过）
```

**设计要点**：
- 每次调用新建 `ConstraintEvaluator` 实例
- 穷举使用 `itertools.product`，上限 100 防止爆炸
- Case 2 和 Case 3 中的"放过"（continue）意味着此约束不拒绝该 pair——可能让不可达 pair 进入 universe

**性能指标**（aclnnFFNV3）：
- 67,893 个原始 pair
- `filter_pairs` 耗时 ~19-24s
- 每 pair 平均 0.3ms

## 6. 生成器层（M4: `generator/`）

### 6.1 CandidateGenerator

#### 6.1.1 构造注入

```python
CandidateGenerator(
    config=GeneratorConfig,
    constraint=ConstraintProtocol | None,
    *,
    random_seed=int | None,
    max_iterations=int = 10000,
    universe=PairUniverse | None,          # 注入后启用贪心模式
    coverage_tracker=CoverageTracker | None,
)
```

`is_greedy = universe is not None and coverage_tracker is not None`

#### 6.1.2 两阶段生成（Phase 1 + Phase 2）

```
generate_candidate(fixed_values=seed) → (TestCase, gain):

  Phase 1: 注入固定值
    遍历 seed 中的参数/属性 → 校验在域内 → 设入 testcase
    收集 fixed_factor_values
    if _use_greedy: total_gain += 固定值组合间的 pair 增益

  Phase 2: 填充剩余属性
    构建 attrs_to_fill（非 seed 属性列表）
    Phase C 排序 → 种子参数优先 + 域小优先
    4 次 attempt:
      1 次贪心 (sort_by_gain=True):
        _backtrack_fill(attrs_to_fill, 0, nodes=[200], sort_by_gain=True)
        → 对每个候选值计算 _compute_incremental_gain
        → 选 gain 最高值
        → _compute_total_gain → _is_valid → 返回

      3 次随机 (sort_by_gain=False):
        _backtrack_fill(attrs_to_fill, 0, nodes=[200], sort_by_gain=False)
        → 通过 _check_value_partial 的候选值 random.shuffle
        → _is_valid → 返回

  全部失败 → raise CandidateGenerationError
```

#### 6.1.3 Phase C — `attrs_to_fill` 排序

**关键代码**（`candidate_generator.py`）：

```python
seed_params = set(fixed_values.keys())
attrs_to_fill.sort(key=lambda item: (
    0 if item[0] in seed_params else 1,   # 种子参数优先
    len(item[2]),                           # 域小优先
))
```

**效果**：DFS 先填充种子参数的剩余属性，尽早触发涉及种子参数的约束检查，减少深层回溯。

**示例**（seed 包含 x.dtype 和 weight1.dtype）：
```
x.is_present(1) → x.format(1) → x.dimension(2) → x.shape_property(4) → x.range_value(10)
→ weight1.is_present(1) → weight1.format(1) → weight1.dimension(2) → ...
→ (其他非种子参数按域大小升序)
```

#### 6.1.4 `_backtrack_fill` — DFS 回溯填充

```python
_backtrack_fill(testcase, attributes, index, uncovered_mask, nodes_remaining, sort_by_gain) → bool:
    if index == len(attributes):          # 全部属性填充完毕
        return True
    if nodes_remaining[0] <= 0:           # 节点预算耗尽
        return False

    (param, attr, domain) = attributes[index]
    candidates = _get_candidates_ranked(param, attr, domain, uncovered_mask, sort_by_gain)

    for value, _ in candidates:
        nodes_remaining[0] -= 1           # 消耗预算
        testcase.add_value(TestValue(param, attr, value))
        if _backtrack_fill(testcase, attributes, index + 1, ...):
            return True
        # 回溯：移除当前值
        del testcase.values[param][attr]
        if not testcase.values[param]:
            del testcase.values[param]

    return False                          # 所有值都失败
```

**参数**：

| 参数 | 当前值 | 说明 |
|---|---|---|
| `nodes` | `[200]` | 单次 attempt 的最大搜索节点数 |
| `sort_by_gain` | True/False | 候选值排序策略（贪心/随机） |
| `attempts` | 1 贪心 + 3 随机 | 每 seed 尝试次数 |

#### 6.1.5 辅助方法

| 方法 | 说明 | 耗时占比 |
|---|---|---|
| `_check_value_partial(testcase, param, attr, value)` | 评估全部约束，判断值在当前部分赋值下是否合法 | **40%** |
| `_compute_incremental_gain(new_value, existing_factors, uncovered_mask)` | 计算新值覆盖的未覆盖 pair 数（位运算） | **23%** |
| `_get_candidates_ranked(param, attr, domain, uncovered_mask, sort_by_gain)` | 过滤候选值 → 贪心按 gain 排序 / 随机 shuffle | **16%** |
| `_compute_total_gain(testcase, uncovered_mask)` | 计算完整 testcase 的增益 | 2% |
| `_is_valid(testcase)` | 约束评估 | <1% |

### 6.2 CoverageDrivenGenerator — 主循环

```python
build() → GenerationResult:
    start_time = time.time()
    iterations = 0
    no_improvement_streak = 0
    max_no_improvement = max(300, candidate_pool_size * 4)

    while coverage_rate < target_coverage AND iterations < max_iterations:
        iterations += 1
        result = _select_best_candidate()
        if result is None:
            no_improvement_streak += 1
            if streak >= max_no_improvement: break
            continue

        best_candidate, gain = result
        if not cache.add(best_candidate):    # 重复
            streak += 1; if streak >= max_no_improvement: break; continue
        if gain == 0:                        # 零增益
            streak += 1; if streak >= max_no_improvement: break; continue

        streak = 0
        pairs = PairBuilder.build(extract_factor_values(best_candidate))
        CoverageTracker.update(pairs)        # 更新位向量
        TestSuite.add(best_candidate)

    return GenerationResult(suite, coverage_rate, iterations, elapsed_time)
```

#### `_select_best_candidate` — 候选选择

```python
_select_best_candidate() → (TestCase, gain) | None:
    seed = PairSeedGenerator.next_seed()
    is_greedy = candidate_generator.is_greedy

    if is_greedy:
        try:
            candidate, gain = candidate_generator.generate_candidate(fixed_values=seed)
        except CandidateGenerationError:
            return None
        if cache.contains(candidate):
            return None
        return candidate, gain

    # 非贪心模式（随机模式）：
    uncovered_mask = coverage_tracker.uncovered_pairs_mask()
    for _ in range(candidate_pool_size):
        try:
            candidate, _ = candidate_generator.generate_candidate(fixed_values=seed)
        except Exception:
            continue
        if cache.contains(candidate):
            continue
        gain = _compute_gain_fast(candidate, uncovered_mask)
        # 位运算: (testcase_mask & uncovered_mask).bit_count()
        if gain > best_gain:
            best_gain, best_candidate = gain, candidate
    return (best_candidate, best_gain) if best_candidate else None
```

### 6.3 PairSeedGenerator — 种子提取

```python
next_seed() → dict | None:
    pair = next_pair()
    return pair_to_seed(pair) if pair else None

next_pair() → Pair | None:
    indices = coverage_tracker.uncovered_indices()
    for idx in indices:
        pair = universe.get_by_index(idx)
        if pair is not None:
            return pair
    return None

pair_to_seed(pair) → dict:
    {"x": {"dtype": "fp16"}, "weight": {"dtype": "int8"}}
```

种子永远是第一个未覆盖 pair（按顺序索引升序）。

## 7. 时间统计工具（`common_utils/timing.py`）

### 7.1 独占时间计算

通过 `threading.local()` 维护的调用栈实现子函数时间扣减。

```
@track 装饰器：

进入 wrapper:
  1. 暂停父级计时（记录 paused 时间点）
  2. 创建自身 entry: {label, start, accumulated=0, _paused=None}
  3. push 入 _track_stack.entries

退出 wrapper:
  1. end = time.perf_counter()
  2. entry = pop()
  3. wall = end - entry['start']
  4. exclusive = wall - entry['accumulated']   ← 子函数时间已累加
  5. 记录 exclusive 到 _registry
  6. 恢复父级:
     parent['accumulated'] += wall
```

### 7.2 接口

| 函数 | 说明 |
|---|---|
| `@track(label)` | 装饰器，统计独占时间 |
| `track_block(label)` | 上下文管理器，统计 wall time |
| `reset()` | 清空所有统计数据 |
| `record_time(label, elapsed)` | 手动记录一次耗时 |
| `print_summary(file=None)` | 输出统计报告 |

## 10. 已知瓶颈

| 瓶颈 | 根因 | 当前开销 | 优化思路 |
|---|---|---|---|
| `_check_value_partial` 评估全部约束 | 未利用依赖关系过滤无关约束 | 314s（40%） | 仅评估涉及当前属性的约束 |
