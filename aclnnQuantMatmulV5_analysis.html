五、根因合成

根本性质：constraint_extraction 的系统性失误——不是单点笔误，而是约束提取在多个正交维度上反复欠约束，每轮补一个缺口又暴露下一个。可拆为 4 层：

  1. prompt v5 transpose_shape 模块系统性误读 x2 收缩维（iter_002 C1 写反）。这是 prompt 级缺陷，每次 re-EXTRACT 都会重新生成错误 expr，supplement 补丁无法根治。需 prompt-optimizer
  2. shape 值关系约束缺失（iter_003 G-B scale）。提取器只约束了维数（dim），未约束 shape 各维的具体值关系（如 ceil(k/128)）。G-B 表给了精确公式但未被落为 expr。
  3. 条件耦合约束缺失（iter_003 bias 3维↔out 维数、iter_001 x2 format↔维数、iter_001 scale groupSize 分支）。文档用“当…时…”表述的条件规则未被提取为分支 expr，而是被并集放宽（如 x2 dimensions=[2,8]、bias 1-3维、scale 1-6维）。
  4. 参数表“并集维度”覆盖了场景级“精确维度”（iter_003 x2Offset 1-2维 vs 公共约束 1维）。提取器取了参数表的宽松上限，未与公共约束的场景级精确值取交。

排除项（已验证）：

  • 非 generator_bug：post_check + independent_eval 均显示生成器忠实满足所给约束（30/30 通过 9 条约束），无 Z3 伪 SAT 或代码 bug。生成器对错误约束的“忠实满足”正是约束失误的下游表现。
  • 非 executor_bug：engine_error 始终空、exit_code=0、CPU golden 干净（case 0 精度对比通过佐证语义有效）、cases_expanded 忠实展开。10 条失败均为 161002 业务参数校验拒绝。

流程缺口：iter_003 达 max-iter=3 后未收口为 MAX_ITERATIONS 终态（terminal_state=null、state=DIAGNOSE），且未产出 analysis.json——诊断循环未闭合，剩余 3 类缺口未被正式定性记录。

优先级 2：prompt 级根治（v5 → v6，杜绝复发）

iter_002 的 C1 转置索引写反是 prompt v5 transpose_shape 模块的系统性误读，supplement 只能临时覆盖。建议 prompt-optimizer 产 v6：

  • 在 transpose_shape 模块明确收缩维 K 的定位规则：K(x1) = tX1 ? shape[-2] : shape[-1]；K(x2) = tX2 ? shape[-1] : shape[-2]（ND 格式）。
  • 增加自检反例（类似 v5 修复“shape size=numel”时的 aclnnForeachErf 反例）：用 aclnnQuantMatmulV5 的 4 个 transpose 分支构造 K 相等校验用例，强制提取器落对索引。
  • 补充“条件分支而非并集”的提取规范：文档“当…时…”必须落为 if-then expr，禁止取并集放宽（覆盖 bias/format/x2Offset/scale 维数等多处）。

优先级 3：流程级修复（避免重蹈）

  • 收口 MAX_ITERATIONS：iter_003 达 max-iter 后应将 run_state 置为 MAX_ITERATIONS 终态并产出 analysis.json，而非停在 DIAGNOSE。当前 terminal_state=null 导致 run 状态不一致。
  • supplement 路径避免 re-EXTRACT：当根因是 prompt 级系统性误读（如 transpose）时，re-EXTRACT 会重新引入错误。应直接 patch constraints.json（cp 上轮 constraints + apply_supplement），仅在 prompt 已修复后再 re-EXTRACT。
  • post_check 可观测性缺口：cases_common.json not found 导致 overall_violation=true 假警（已记录但非真实违规），应修复 common 桶观测以减少误判噪音。
