1. P0-6.1 幂等注册 prod/sum/tensor-sum 递归函数

问题定位
expression_preprocess_utils.py 三个方法用 per-builder slice_id 命名 RecFunction，跨 case 撞名：
_sum_z3_sequence(747-770) → __sum_seq_{slice_id}；_prod_z3_sequence(772-785) → __prod_seq_{slice_id}；_sum_tensor_elements(787-817) → __sum_tensor_{name}_{slice_id}。
_slice_counter 每个 Z3ConstraintBuilder 实例从 0 重置（z3_expression_solver_utils.py:137），全模块共用 z3.main_ctx() → 第二个 case 即抛 recursive function ... already defined → 被 add_constraint 的 except 吞掉（:197-198）→ 约束丢弃 → 伪 SAT。已用 z3 5.0.0 实证复现。
已有修法
param_var_definition.py:32-48 _get_or_register_prod_shape + 模块级 _PROD_SHAPE_REC_FUNCS（按名幂等注册，已用于 shape 总元素数路径）。本方案把同构模式套到 expr 路径。
ten.html 缺陷
① 只点名 _prod_z3_sequence/_sum_z3_sequence，漏 _sum_tensor_elements（同 bug 模式）；② 片段硬编码 "__prod_seq_global"，注册表键用 (str(seq_sort),)——若同进程出现不同 seq_sort，不同键不早返回却同名注册仍撞名。本计划改为函数名从 sort 派生，消除隐患。

改动 1.1 — 新增模块级注册表与幂等助手（expression_preprocess_utils.py 顶部）

# 与 param_var_definition._PROD_SHAPE_REC_FUNCS 同构：模块级、跨 builder 共享 z3.main_ctx()
_PROD_SEQ_REC_FUNCS   = {}   # key: str(seq_sort)               -> ProdSeq
_SUM_SEQ_REC_FUNCS    = {}   # key: (str(seq_sort), str(elem)) -> SumSeq
_SUM_TENSOR_REC_FUNCS = {}   # key: str(element_sort)          -> SumArr

def _rec_suffix(element_sort):
    if element_sort is None or element_sort == z3.IntSort(): return "int"
    if element_sort == z3.RealSort(): return "real"
    return "other"   # 兜底，避免同名不同 sort 撞名

def _get_or_register_prod_seq(seq):
    seq_sort = seq.sort()
    existing = _PROD_SEQ_REC_FUNCS.get(str(seq_sort))
    if existing is not None: return existing(seq)          # 复用，不再 RecAddDefinition
    name = f"__prod_seq_{_rec_suffix(z3.IntSort())}"  # 名字从 sort 派生，非硬编码
    P = z3.RecFunction(name, seq_sort, z3.IntSort())
    v = z3.Const(f"{name}_arg", seq_sort)
    z3.RecAddDefinition(P, [v],
        z3.If(z3.Length(v) == 0, z3.IntVal(1),
              v[0] * P(z3.SubSeq(v, 1, z3.Length(v) - 1))))
    _PROD_SEQ_REC_FUNCS[str(seq_sort)] = P
    return P(seq)

def _get_or_register_sum_seq(seq, element_sort):
    if element_sort is None: element_sort = z3.IntSort()
    seq_sort = seq.sort()
    key = (str(seq_sort), str(element_sort))
    existing = _SUM_SEQ_REC_FUNCS.get(key)
    if existing is not None: return existing(seq)
    name = f"__sum_seq_{_rec_suffix(element_sort)}"     # int/real 两键，对应 ten.html 注记
    zero = z3.IntVal(0) if element_sort == z3.IntSort() else z3.RealVal(0)
    S = z3.RecFunction(name, seq_sort, element_sort)
    v = z3.Const(f"{name}_arg", seq_sort)
    z3.RecAddDefinition(S, [v],
        z3.If(z3.Length(v) == 0, zero,
              v[0] + S(z3.SubSeq(v, 1, z3.Length(v) - 1))))
    _SUM_SEQ_REC_FUNCS[key] = S
    return S(seq)

def _get_or_register_sum_tensor(element_sort):
    existing = _SUM_TENSOR_REC_FUNCS.get(str(element_sort))
    if existing is not None: return existing
    array_sort = z3.ArraySort(z3.IntSort(), element_sort)
    name = f"__sum_tensor_{_rec_suffix(element_sort)}"
    zero = z3.IntVal(0) if element_sort == z3.IntSort() else z3.RealVal(0)
    A = z3.RecFunction(name, array_sort, z3.IntSort(), z3.IntSort(), element_sort)
    a = z3.Const(f"{name}_arr", array_sort)
    s = z3.Int(f"{name}_start"); e = z3.Int(f"{name}_end")
    z3.RecAddDefinition(A, [a, s, e],
        z3.If(s >= e, zero, z3.Select(a, s) + A(a, s + 1, e)))
    _SUM_TENSOR_REC_FUNCS[str(element_sort)] = A
    return A

改动 1.2 — 三个方法改用幂等助手（保留原递归体与副作用）

# _prod_z3_sequence: 改为单行委托，递归体已移入助手
def _prod_z3_sequence(self, seq):
    return _get_or_register_prod_seq(seq)

# _sum_z3_sequence: 同上，element_sort 透传
def _sum_z3_sequence(self, seq, element_sort=None):
    return _get_or_register_sum_seq(seq, element_sort)

# _sum_tensor_elements: 保留 rank==1 副作用与返回表达式，仅把 RecFunction 注册换为幂等
def _sum_tensor_elements(self, tensor_var):
    arr = tensor_var.range_value
    element_sort = tensor_var.get_element_sort()
    SumArr = _get_or_register_sum_tensor(element_sort)   # 幂等，不再 slice_id 命名
    shape = tensor_var.shape if isinstance(tensor_var, TensorVar) else tensor_var.elem_shape
    rank = z3.Length(shape)
    self.builder.solver.add(rank == 1)                   # 副作用保留（per-call，非函数定义）
    return SumArr(arr, z3.IntVal(0), shape[0])

2. P0-6.2 add_constraint 失败可观测（不静默丢约束）

问题
z3_expression_solver_utils.py:197-198 的 except Exception 仅记 logger.error，丢弃的约束无任何标志位，solve() 仍以"部分约束"返回 sat 并落盘——伪 SAT 的制度性入口。
ten.html 缺陷
方案给"post_check 复算或直接判 unknown"两选项。"直接判 unknown" 会回归：若某当前通过算子存在被静默丢但冗余/巧合满足的 expr，强制 unknown 会把它从通过变 0 用例。本计划只做可观测，阻断统一交给 6.3 的 post_check，不引入 force-unknown。

3. P1-6.3 post_check 纳入生成主流程 + 针对性编码增强

3a — 接入 post_check 到 generate_cases.py（post_check 已参数化）

现状
scripts/post_check_cases.py 已参数化（--iter-dir/--constraints CLI、写 post_check_report.json、逐平台 eval constraints_in_parameters），无需再改硬编码。6.3a 仅剩接入主流程 + 抽出可复用入口。
改动：post_check_cases.py 抽出 run_post_check(iter_dir, constraints_path) -> report（含每平台 violating_case_ids 全量，供过滤），main() 薄封装。generate_cases.py 增 --post-check（默认开）/--no-post-check：生成后调 run_post_check，对有违例平台过滤违例用例并补采至 case_count（新 seed 重生成→post_check→留通过用例，上限 3×case_count 防死循环），不足则如实落盘并标 post_check_shortfall。
接入：scripts/generate_cases.py 生成 cases_*.json 后，若 --post-check（默认开），调用 post_check；对 overall_pass=false 的平台，过滤违反用例并补采至 case_count，补采设上限（如 3 轮 × case_count）防死循环；仍不足则如实落盘并标注 post_check_shortfall。

3b — post_check eval 保真边界（防误杀通过用例）

  • range_value 列表/元组型：range_values 可能为标量、[min,max] 列表或元组；0 <= param.range_value 在列表型上抛 TypeError。不扩展 __eq__ 语义（避免把坏用例判成通过），改由下方 eval-error 门禁兜住：抛错即不可信、不过滤。
  • 读对文件：post_check 读 cases_<platform>.json（已展开），不读紧凑 cases.json（诊断时两者都要看，见 CLAUDE.md 约定）。
  • eval-error ≠ 违例：每 expr 返回 (ok, err)。仅 err is None 且 ok=False 才算真违例（可过滤、计入 violated_count）；err 非空标 eval_unreliable，绝不据此过滤或计入违例——防 range_value 列表型等误杀通过用例。该 expr 仅告警。

改动 4.1 — 新建模块文件

--- prompts/modules/aclnnFusedLinearCrossEntropyLossGrad.md ---
module: aclnnFusedLinearCrossEntropyLossGrad
description: 修正文档参数表↔公式冲突：weightGradOut.shape[1] 绑 H 不绑 BT；maskedTarget/targetMask 值域
triggers:
  - kind: operator_name_eq
    value: "aclnnFusedLinearCrossEntropyLossGrad"
depends_on: []
---
## 算子专属提取规则（消解文档自相矛盾，非通用模式）

1. weightGradOut.shape[1] 必须绑 input.shape[1]（=H），不得绑 grad.shape[0]（=BT）
   - 文档参数表（weightGradOut 行）写"第2维长度与输入grad长度相同"（=BT），与公式第49行
     grad_weight = softmax^T · input ∈ R^{V×H}（第2维=H）矛盾。
   - 以公式为准：NPU 运行时 Expected [V,H]；失败例 BT=8、H=128 证明 BT≠H 才是常态，
     强制 BT==H 会退化测试。落 expr：weightGradOut.shape[1] == input.shape[1]
     （等价 == weight.shape[1]，因已有 weight.shape[1]==input.shape[1]）；
     禁止 weightGradOut.shape[1] == grad.shape[0]。
2. maskedTarget ∈ [0, weight.shape[0]-1]：局部词表索引，负值越界触发 aicore 507015。
   expr：0 <= maskedTarget.range_value and maskedTarget.range_value <= weight.shape[0] - 1。
3. targetMask ∈ [0,255]：dtype=UINT8，8bit 掩码。
   expr：0 <= targetMask.range_value and targetMask.range_value <= 255。
4. 维护注记：本模块为消解文档参数表↔公式冲突的算子专属纠错；若官方文档修订使二者一致，应同步删除本模块。
